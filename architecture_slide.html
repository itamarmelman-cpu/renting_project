AguGo Renting System

End-to-End Architecture — from Browser to Physical Locker

Client
🛍️ CatalogPage
Browse products, full-text search, add to cart, choose rent duration
🛒 CartPage
Adjust quantities, remove items, review subtotal
💳 CheckoutPage
Enter name, pick payment provider (Apple Pay / Google Pay / etc.), submit order
🔐 LockerPage
3-step UI: Open → Collect → Close locker
↩️ ReturnPage
Look up rentals by name, select items, open locker to return
📅 ReservationPage
Reserve products up to 5 days in advance; collect later
🔑 InventoryPage
Admin (login required): manage products & stock levels
HTTP REST (JSON)
API
🐍 Flask Server — app.py
  • POST /api/orders — create order, deduct stock
  • POST /api/reservations — hold stock 5 days
  • POST /api/reservations/:id/collect — convert to order
  • POST /api/validate-return — pre-check return eligibility
  • POST /api/returns — record return, restore stock
  • GET /api/returns/lookup — active rentals by customer
  • POST /api/locker/open|close — hardware trigger
  • POST /api/locker/callback — receive Arduino confirmation
  • GET|POST|PUT|DELETE /api/products — catalog CRUD (admin)
🔒 LockerController
Proxies open/close to Node.js bridge on localhost:5001

Waits up to 30 s for Arduino callback event before timing out
Python function calls
Data
🗄️ Database — database.py
Thread-safe singleton (RLock). In-memory dicts + atomic JSON writes via temp-file swap.
📦 products.json
Catalog: id, name, price, stock, type (rent/buy), category, image
🧾 orders.json
Completed orders: customer, provider, total, items[ ], status
📋 reservations.json
Holds: items held with 5-day expiry; auto-cancelled + stock restored on expiry
↩️ returns.json
Return log: customer, product, qty, returned_at; triggers stock increment
HTTP (localhost:5001)
Bridge
🌉 Node.js Arduino Bridge
Runs on localhost:5001. Translates HTTP commands to serial port commands.

Tracks state in memory (open / closed). On hardware response, POSTs callback to Flask.
Serial (9600 baud)
Hardware
🔌 Arduino — locker.ino
  • Listens for OPEN\n / CLOSE\n / STATUS\n on serial
  • Drives servo motor (pin 9): 0° = locked, 180° = open
  • Animates 4 NeoPixels: red = locked, green = open
  • Persists state in EEPROM across power cycles
  • Replies OPENED / CLOSED after 3.8 s servo travel
🗝️ Physical Locker
Servo arm mechanically engages / disengages the latch.

Customer collects or returns rental items when door is open.

Key User Flows

🛍️ Order & Collect

1
User browses Catalog, adds items to cart, chooses rental days
↓
2
Checkout: enter name & payment provider → POST /api/orders
↓
3
Flask validates stock, creates order record, decrements stock in DB
↓
4
Success → LockerPage: user clicks "Open Locker"
↓
5
Flask → Node.js bridge → Serial OPEN\n → Arduino servo unlocks (3.8 s)
↓
6
Arduino sends OPENED → bridge POSTs callback → Flask resolves response
↓
7
User collects items → clicks "Close Locker" → servo locks → done ✓

↩️ Return Items

1
User opens ReturnPage, enters first & last name
↓
2
GET /api/returns/lookup → DB finds active rentals (rented − returned)
↓
3
User selects items to return → POST /api/validate-return
↓
4
DB checks: product is rental type & customer has outstanding units
↓
5
Locker opens (same Arduino path as Order flow)
↓
6
User places items in locker → closes door
↓
7
POST /api/returns → DB records return, restores stock → done ✓

📅 Reserve & Collect Later

1
User opens ReservationPage, selects products & quantities
↓
2
POST /api/reservations → DB deducts stock immediately, creates hold
↓
3
Reservation valid for 5 days. If not collected → auto-expired, stock restored
↓
4
User returns with reservation ID → CollectReservationPage
↓
5
Selects rent duration per item → POST /api/reservations/:id/collect
↓
6
DB converts reservation to order (no additional stock deduction)
↓
7
Locker opens → collect items → locker closes → done ✓

🔐 Locker Control — Detailed Sequence

🖥️ Browser
🐍 Flask
🌉 Node Bridge
🔌 Arduino
🗝️ Locker
POST /api/locker/open
▶
forward to :5001/open
▶
write "OPEN\n" to serial
▶
servo 0°→180°, LED green (3.8 s)
▶
latch opens ✓
reply "OPENED\n"
◀
POST /api/locker/callback {status:"open"}
◀
{status:"open"} → UI shows green ✓
◀
Flask holds the HTTP request open (Event.wait, max 30 s) until the Arduino callback resolves it — no polling needed.
